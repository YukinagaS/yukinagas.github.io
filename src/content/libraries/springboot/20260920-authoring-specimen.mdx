This document establishes the baseline writing vocabulary for the library. It
includes **strong text**, *emphasis*, `inline code`, an
[external link](https://mdxjs.com/), and an
<abbr title="Markdown JSX">MDX</abbr> abbreviation.

The entry title, subtitle, date, and tags appear in the entry header, so the
MDX body begins with a level-three heading.

---

### Headings and text hierarchy

Body content should begin at level three because the entry title is rendered
as a level-two heading by `LibraryEntry`.

#### A level-four subsection

Paragraphs should remain comfortable to read across several lines. The content
column should constrain its line length without preventing tables, figures, or
code samples from using the available width.

Inline technical terms such as `generateStaticParams`, `npm run build`, and
`LibraryEntryDefinition` should remain distinct without overwhelming the
surrounding prose.

### Lists

An unordered list:

- Keep content close to the subject it documents.
- Prefer ordinary Markdown when it expresses the structure clearly.
- Introduce components only when they add meaningful behavior or semantics.
  - Nested items should be visibly subordinate.
  - Their indentation should remain clear on narrow screens.

An ordered process:

1. Write the entry.
2. Validate its metadata.
3. Derive its date and ID from the filename.
4. Render it during the static build.
5. Inspect it at desktop and mobile widths.

### Quotation

> A useful knowledge library should make writing easier than maintaining the

A block quotation should be visually distinct from ordinary prose without

### Callouts

<aside data-callout="note" aria-label="Note">
  <strong>Note:</strong> A note supplies useful context that is not essential
  to completing the surrounding procedure.
</aside>

<aside data-callout="tip" aria-label="Tip">
  <strong>Tip:</strong> Prefer a descriptive filename because its slug becomes
  the entry’s permanent section identifier.
</aside>

<aside data-callout="warning" aria-label="Warning">
  <strong>Warning:</strong> Renaming a published entry changes its anchor unless
  the slug portion of the filename remains unchanged.
</aside>

<aside data-callout="important" aria-label="Important">
  <strong>Important:</strong> Every entry must provide a title, subtitle, and
  non-empty collection of tags.
</aside>

These callouts deliberately use native `aside` elements and `data-callout`
attributes. They can be styled now and replaced by a reusable component later
if that would improve the authoring experience.

### Code

A short inline expression looks like `const ready = true`.

**File: `example.ts`**

```ts
type LibraryEntryMetadata = {
  title: string;
  subtitle: string;
  tags: string[];
};

export function describeEntry(
  metadata: LibraryEntryMetadata,
): string {
  return `${metadata.title}: ${metadata.subtitle}`;
}
```

The code block should support:

- A visible language or filename label
- Horizontal scrolling for long lines
- Preserved indentation
- Syntax highlighting
- An eventual copy button

**Terminal example**

```shell
npm run lint
npm run build
```

### Expandable details

<details>

Replace the moving rectangle with a character that idles and walks using frames
selected from a sprite sheet.

---

### Learning goals

- Load an image asset once and reuse it.
- Use Quads to select rectangular regions of a sprite sheet.
- Advance animation using elapsed time instead of rendered frame count.
- Keep animation state separate from movement state.
- Flip a sprite without maintaining a duplicate set of artwork.

### Select frames with Quads

A sprite sheet stores several frames in one texture. A LÖVE `Quad` describes a
rectangular region of that texture. The image stays loaded once while each Quad
tells `love.graphics.draw` which region to render.

For this example, provide `assets/images/hero.png` with four adjacent 16×16
frames in a single 64×16 row. Set the texture filter before loading the image so
pixel art remains crisp when scaled.

```lua
local sheet
local frames = {}
local frameSize = 16

function love.load()
    love.graphics.setDefaultFilter("nearest", "nearest")
    sheet = love.graphics.newImage("assets/images/hero.png")

    local sheetWidth, sheetHeight = sheet:getDimensions()

    for i = 1, 4 do
        frames[i] = love.graphics.newQuad(
            (i - 1) * frameSize,
            0,
            frameSize,
            frameSize,
            sheetWidth,
            sheetHeight
        )
    end
end
```

Quad coordinates identify a region inside the source image. The position passed
to `love.graphics.draw` identifies the frame’s destination in the world.

### Give animation its own clock

At eight animation frames per second, each frame lasts `1 / 8` seconds.
Accumulate `dt`, subtract one frame duration whenever enough time has elapsed,
and advance the frame index.

```lua
local frameIndex = 1
local animationTime = 0
local frameDuration = 1 / 8

local function updateAnimation(dt)
    animationTime = animationTime + dt

    while animationTime >= frameDuration do
        animationTime = animationTime - frameDuration
        frameIndex = frameIndex % #frames + 1
    end
end

function love.update(dt)
    updateAnimation(dt)
end
```

Subtracting the duration preserves excess elapsed time. Resetting the timer to
zero discards that remainder and can make animation uneven. The `while` loop can
also catch up after a frame spans several animation intervals; a single `if`
would advance only once.

### Draw from a stable origin

Use negative x-scale to face left. Supplying the center of a 16×16 frame as the
draw origin keeps the mirrored sprite anchored instead of making it jump to the
other side of its position.

```lua
function love.draw()
    local facing = player.facingLeft and -1 or 1

    love.graphics.setColor(1, 1, 1, 1)
    love.graphics.draw(
        sheet,
        frames[frameIndex],
        player.x,
        player.y,
        0,
        facing,
        1,
        8,
        8
    )
end
```

Animation and movement are related but separate state. Switch to idle only when
the selected animation actually changes, and reset its timer once during that
transition. Resetting the walking timer during every moving frame prevents it
from advancing.

Each entity needs its own mutable frame index and timer. Entities may share the
same image, Quads, and animation definitions, but a shared timer forces every
instance to animate in lockstep. A non-looping attack should clamp to its final
frame and report completion instead of wrapping.

### Represent animation as data

Definitions make it possible to reuse one update function for idle, walking,
and later attacks.

```lua
local animations = {
    idle = {
        frames = { 1 },
        frameDuration = 1,
        looping = true,
    },
    walk = {
        frames = { 1, 2, 3, 4 },
        frameDuration = 1 / 8,
        looping = true,
    },
}

local animator = {
    name = "idle",
    frame = 1,
    elapsed = 0,
}
```

The animation definition is shared immutable data. The animator is per-entity
state that records which animation is active and where that entity is within
it.

### Build sequence

1. Load the sprite sheet during `love.load`.
2. Generate Quads from its regular row of frames.
3. Define idle and walking animations as data.
4. Advance the active animation with an elapsed-time clock.
5. Change animation only when movement state changes.
6. Flip the character around its center when facing left.

### Verify the result

- Temporarily slow the animation to two frames per second and inspect every
  Quad.
- Turn left and right without changing position; the sprite should remain
  anchored.
- Stop and resume movement without continually resetting the timer.
- Spawn a second character and confirm that its animation timer is independent.
